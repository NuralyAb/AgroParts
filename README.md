# AgroParts

Маркетплейс сельхоззапчастей Казахстана (пилот — Костанай) со встроенной CRM, складским учётом, кассой и интерактивным 3D-каталогом техники. Техническое задание — [data.md](data.md).

**Главный принцип:** маркетплейс и CRM магазинов работают с **одной** системой учёта товаров, заказов и остатков. Продажа на кассе сразу уменьшает остаток на маркетплейсе, онлайн-бронь сразу видна продавцу как резерв.

```
Доступно = Физический остаток − Активные резервы
```

## Быстрый старт (без Docker)

Нужны Python 3.12 и Node.js 18+.

```powershell
# backend — http://127.0.0.1:8000, документация API: /docs
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m app.seed          # демо-данные (SQLite)
.venv\Scripts\python -m uvicorn app.main:app --port 8000

# frontend — http://localhost:5173 (проксирует /api на backend)
cd frontend
npm install
npm run dev
```

## Архитектура

Модульный монолит FastAPI: одна БД и одна транзакция на операцию, строгие границы модулей.

| Модуль | Что делает |
| --- | --- |
| [catalog](backend/app/modules/catalog) | Единые карточки запчастей (Part), OEM-номера и артикулы, техника, совместимость с источником, проверенные аналоги, поиск |
| [shops](backend/app/modules/shops) | Магазины, сотрудники, склады / точки выдачи, проверка администратором |
| [inventory](backend/app/modules/inventory) | Предложения магазинов (Offer), остатки по складам, резервы, журнал движений. **Единственное место, где меняются остатки** — [service.py](backend/app/modules/inventory/service.py) |
| [orders](backend/app/modules/orders) | Заказы всех каналов (маркетплейс, телефонная бронь, касса), статусы, истечение броней, оплата (заглушка), уведомления (заглушка) |
| [crm](backend/app/modules/crm) | Клиенты магазина, история покупок, статистика |
| [garage](backend/app/modules/garage) | «Мой гараж», избранное, подбор по технике |
| [viewer3d](backend/app/modules/viewer3d) | 3D-модели и компоненты; каждый кликабельный компонент связан с записью каталога |
| [integrations](backend/app/modules/integrations) | Импорт Excel/CSV, адаптер 1С по API-ключу, сопоставление с каталогом |
| [admin](backend/app/modules/admin) | Проверка магазинов, очередь сопоставления, модерация совместимости и аналогов, пользователи, статистика |

Как защищены остатки:
- строки остатков блокируются (`SELECT … FOR UPDATE` в PostgreSQL, `BEGIN IMMEDIATE` в SQLite) в порядке id, чтобы параллельные заказы не взаимоблокировались;
- заказ и все его резервы фиксируются одной транзакцией: если на одну позицию не хватило, ничего не резервируется;
- касса продаёт только свободный остаток, инвентаризация не может опустить остаток ниже резервов;
- `CHECK (reserved <= on_hand)` в БД — последний рубеж;
- каждое изменение пишется в `stock_movements`, каждая смена статуса заказа — в `order_events`.

Достоверность наличия: у предложения есть режим учёта. `tracked` — остатки ведутся в AgroParts или приходят из 1С, наличие гарантируется. `manual` — магазин грузит Excel, покупатель видит «наличие подтвердит продавец» и время последнего обновления.

Сопоставление: автоматически принимается только однозначное совпадение нормализованного номера (`4нв-4330` = `4HB 4330`). Остальное уходит в очередь администратора с подсказками. Совместимость и аналоги видны покупателям только после проверки.

Frontend: React + TypeScript + Vite, React Three Fiber для 3D (three.js грузится отдельным чанком), интерфейс на русском и казахском.

### Поиск

[catalog/search.py](backend/app/modules/catalog/search.py) — индекс каталога в памяти, перестраивается при изменении каталога или предложений:
- номера: точное совпадение OEM/артикула, начало и часть номера, опечатка в номере (`4нв-4330` = `4HB 4330`);
- слова: падежи и окончания («ремня», «подшипники»), опечатки («подшыпник», «филтр»), префиксы при наборе («подш»);
- неверная раскладка: `htvtym` → «ремень»;
- ранжирование по релевантности, фасеты по категориям, сортировка; подсказки при вводе — `/api/catalog/suggest`.

Для пилота (тысячи позиций) это миллисекунды; при росте модуль заменяется Meilisearch/OpenSearch с тем же интерфейсом.

### 3D

- [three/models.tsx](frontend/src/three/models.tsx) — процедурные модели техники (комбайн, классический трактор, К-701 с шарнирной рамой): на главной витрина с точками-подсказками на деталях (цены из каталога) и миниатюры в подборе по технике.
- [three/parts.tsx](frontend/src/three/parts.tsx) — 3D-модели запчастей: на странице товара деталь можно вращать, а для карточек из них рендерятся PNG:
  ```powershell
  cd backend; .venv\Scripts\python scripts\render_part_images.py   # нужен запущенный npm run dev и Edge/Chrome
  ```
- 3D-каталог Дон-1500Б: узлы хранятся в БД (`model_components`) и привязаны к записям каталога.

## Что пока упрощено

- **3D:** модели техники и деталей процедурные (стилизованные). Загрузка настоящих GLB-моделей (поле `glb_url`) ещё не реализована во вьюере.
- **Изображения товаров** — рендеры 3D-моделей. Реальные фото магазины смогут загружать сами (поля `image_url`, `image_credit` есть); автоматически брать фото из интернета нельзя из-за авторских прав.
- **Оплата:** `MockProvider` — нужно подключить реальный эквайринг (Kaspi Pay, банки).
- **Уведомления** пишутся в лог; нужны SMS / WhatsApp / Telegram через очередь (Redis).
- **Схема БД** создаётся через `create_all`; для production нужны миграции Alembic.
- **Поиск** работает через LIKE по нормализованному тексту. В PostgreSQL нужен индекс `pg_trgm` на `parts.search_text`, позже — отдельный поисковый движок.
- **Регистронезависимый поиск по кириллице** в списках CRM/склада (`ILIKE`) в SQLite работает только для латиницы; в PostgreSQL работает полностью.
- **Загрузка фото** в S3/MinIO не сделана; картинки сейчас раздаются backend из `backend/media`.
- **Казахский перевод** — черновой, только навигация и ключевые подписи; нужна вычитка носителем языка.
- **OCR и ML-сопоставление** (ТЗ 5.5) — точка расширения в [matching.py](backend/app/modules/integrations/matching.py).
